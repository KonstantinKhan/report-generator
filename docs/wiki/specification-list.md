# Ведомость спецификаций

Отчёт «Ведомость спецификаций» (ВС, ГОСТ Р 2.106) — перечень всех сборочных единиц и комплектов изделия, по одной строке
на объект, с колонкой «Куда входит»: в каких спецификациях объект встречается и в каком количестве. Исходные данные —
та же структура PDM, что у [Спецификации](specification-table-format.md), но другой обход (весь состав на любой глубине)
и другой лист.

Точка входа: `specificationList(data, customerRepresentative)` (`SpecificationList.kt`), данные:
`PdmNode.toSpecificationListData()` (`SpecificationListData.kt`), адаптер в контекст шаблона —
`SpecificationListDataContext.kt`, запрос структуры — `specificationListQuery` / `loadSpecificationListStructure`
(`SpecificationListQuery.kt`). Шаблон листа: `report-ir/src/main/resources/templates/gost-spec-list.yaml`,
`GostSpecTemplate.LIST_LANDSCAPE`.

HTTP: `POST /specification-lists/{versionId}` (query `customerRepresentative`, по умолчанию `true`). Ответ тот же, что у
`/specifications/{versionId}` (`SpecificationResponse`: `id`, `path` к PDF). `versionId` не целое — 400. Ошибка данных
(`SpecificationDataException`: нет спецификации у корня, нет обозначения у спецификации, нет количества у связи) — 502
через общий `StatusPages`, как у спецификации.

## Обход структуры и правила строк

Обход рекурсивный, от корня на любую глубину по связям состава с объектами «Сборочная единица» и «Комплект». Корень в
строки не попадает. Для каждого потомка:

- Объект с документом типа «Ведомость» и «Код документа» = «ВС» пропускается вместе с поддеревом (не обходится).
- Объект без документа «Спецификация» не строка, но его потомки обходятся. Из такого объекта «Куда входит» не выводится:
  потомок получает родителей только по своим связям с объектами, у которых есть спецификация.
- Одна строка на объект (каждый объект обходится один раз). Родители — связи из обойдённых объектов со спецификацией
  (корень тоже родитель: его обозначение — обозначение его спецификации, а не обозначение изделия).
- «Общее кол.» — сумма количеств связей по всем родителям. Для диапазона количества берётся нижняя граница.
- Детали, материалы и стандартные изделия в строки не попадают.

Секции в порядке листа: «Сборочные единицы» (ASSEMBLY), затем «Комплекты» (KIT). Внутри секции — сортировка как у
спецификации (`SpecificationOrder.sortedByDesignationAndName`). Пустая секция заголовка не получает (`skipEmpty`).

## Лист и геометрия

- A3 ландшафт: 420 x 297 мм. В коде это локальная константа `A3_LANDSCAPE` в `SpecificationList.kt`: `PageFormat.A3` в
  `report-geometry` — портретный лист 297 x 420, альбомного A3 там нет (для A4 есть `A4_LANDSCAPE`).
- Поля: left 20, top 5, right 5, bottom 5 мм (левое 20 мм — подшивка). Рабочая рамка 395 x 287 мм, начало в (20, 5).
- Блоки статического шаблона (`gost-spec-list.yaml`) — те же, что у групповой спецификации: штамп первого листа 185 x 40,
  штамп продолжения 185 x 15 (поле «Лист» и номер листа), «Копировал» / «Формат» под рамкой в нижнем поле. Левой полосы
  (`leftMargin`, `specLeft`) нет.

## Колонки и шапка

Сумма ширин 395 мм = рабочая рамка. Тело — flow-таблица, одна строка = один объект (8 мм на строку листа).

| Колонка | Ширина, мм | Примечание |
|---|---|---|
| № строки | 7 | номер физической строки (движок, `${line.number}`), см. «Нумерация строк» |
| Обозначение | 70 | обозначение спецификации объекта |
| Наименование | 130 | |
| Куда входит — Обозначение | 70 | обозначение спецификации родителя, по одной строке на связь |
| Куда входит — Кол. | 10 | количество связи с родителем, на той же строке |
| Общее кол. | 12 | сумма количеств, только на первой строке записи |
| Примечание | 96 | пусто в этой версии |

Шапка двухуровневая, 20 мм, на каждой странице (`repeat: true`): верхний уровень 6 мм («Куда входит» над двумя колонками),
нижний 14 мм («Обозначение», «Кол.»). «№ строки», «Общее кол.» — повёрнуты на 90°, занимают оба уровня (rowSpan 2),
«Обозначение», «Наименование», «Примечание» — тоже на оба уровня. Тонкая линия между «Куда входит» и его колонками.

## Записи с несколькими родителями

Объект с несколькими родителями — одна запись (одна строка данных) на несколько физических строк листа. Объединения ячеек нет:
первая физическая строка несёт обозначение, наименование и «Общее кол.»; каждая следующая — только строку родителя
(обозначение и количество). Высота физической строки — 8 мм, как и у записи с одним родителем.

## Нумерация строк

Правило: номер получает каждая физическая строка записи данных, счёт сквозной по всем группам и страницам листа.

- Номер ставит движок (`report-layout`, `${line.number}` в ячейке строки потока, раздел `lines: {start: 1, scope: table,
  fill: true}` в `gost-spec-list.yaml`). Поле `number` в данных записи нет: номер не вычисляется кодом листа.
- Нумеруются все физические строки записи: и первая, и строки-продолжения для второго, третьего… родителя.
- Нумеруются пустые строки дозаполнения до низа рамки (`fill: true`). Они получают номера того же счётчика и идут после
  последней строки данных страницы. Если на странице нет места хотя бы под одну целую строку (remainder `gap`, см. ниже),
  строк дозаполнения нет и номеров тоже.
- НЕ нумеруются (движок пока не умеет, см. «Ограничения нумерации»): заголовки групп («Сборочные единицы», «Комплекты»),
  пустые спейсеры вокруг заголовка, строки итогов.
- Перенос записи на следующую страницу номер не сбрасывает: продолжение получает следующий номер (пропусков и повторов нет).
- Пример (золотой эталон `list-multi-page-pz`): номера записей и дозаполнения на страницах 1..172 идут подряд без повторов.

### Ограничения нумерации

- Заголовки групп и спейсеры: номер ставится только на `numbered`-строки записей (`report-layout/.../TableMeasurement.kt`:
  заголовок группы `:338`, спейсеры `:352-354`, подзаголовок `:318` — `numbered = false`). Опции в шаблоне для них нет.
- Поэтому в колонке «№ строки» на строках заголовков групп и спейсерах пусто: счёт продолжается, номера 1..N подряд только
  у строк записей и дозаполнения.
- Остаток высоты на первой странице (ПЗ занимает низ, remainder `gap`): если под зазором не помещается целая строка 8 мм,
  дозаполнения нет, номеров там нет.

## Блок ПЗ (представитель заказчика)

Опциональная таблица 120 x 22 мм (флаг `customerRepresentative`, по умолчанию включён) в правом нижнем углу рамки, над
основной надписью (смещение 40 мм вверх). Нижняя ячейка 8 мм, по центру, шрифт 7 — «Индекс заказчика» корня
(`customerIndex`). Без значения (атрибута нет, пусто, пробелы) ячейка пустая (`optional`). Когда ПЗ выключен, таблица
не выводится, текст индекса не попадает в лист.

## Тесты

- `SpecificationListDataTest` — сбор данных: пропуск узла с «ВС» вместе с поддеревом, список с другим кодом не пропускается,
  несколько родителей, сумма «Общее кол.», объект без спецификации (пропуск, потомки обходятся), родитель первого уровня =
  спецификация корня, порядок секций и сортировка, детали не строки, записи данных без номера (номер — движок) и строки данных контекста шаблона,
  строки родителей по одной на связь, пустой состав, индекс заказчика, корень без спецификации — ошибка.
- `SpecificationListTest` — шаблон загружается (7 колонок тела), лист раскладывается, пустой список — одна страница.
- `SpecificationListGoldenTest` — дамп раскладки четырёх фикстур (`src/test/resources/golden/list-*.txt`): одна страница с ПЗ
  и без, несколько страниц с ПЗ и без (шапка и штамп продолжения на страницах 2+). Файлы создаются при первом прогоне,
  если их нет (как у остальных golden модуля); `GOLDEN_PDF_DIR=<dir>` дополнительно пишет PDF для визуальной проверки.

## Ограничения

- Обход «ВС» — по пути: поддерево пропускается на пути через узел с «ВС». Тот же объект, достижимый из другого (не ВС)
  узла, попадёт в список. Если нужно иначе — решение по правилу, в коде не менялось.
- Запись может разорваться между страницами: физические строки родителей переходят на следующую страницу с продолжением
  номера, без обозначения и наименования (строка выглядит как продолжение). Удержание записи целиком в шаблоне не настроено
  (`keep` только для заголовка).
- На страницах 2+ остаток высоты уходит в последнюю строку страницы (`remainder: stretch`), поэтому последняя строка
  страницы может быть выше 8 мм.
- «Примечание» пустое (в ТЗ не описано, колонка оставлена).
- Формат количества — как у спецификации для не материалов: целое, округление half-up; диапазон — нижняя граница.
- Макета листа не было: размеры взяты по образцу групповой спецификации и заданию на шапку (6 + 14 мм, колонки 7/70/130/70/10/12/96).
