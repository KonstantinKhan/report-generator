# Известные незакрытые места

Честный список того, что упрощено или не сделано: сознательно, не забыто. Список сверен с кодом на 2026-10-03
(ветка `engine`, HEAD `81fa21d`). Ничто из этого не блокирует дальнейшую работу, но стоит держать в голове перед
тем, как строить сверху что-то, что этих гэпов не переживёт. Закрытое в ветке `engine` см. в конце страницы и в
[changelog-engine.md](changelog-engine.md).

## Layout Engine

- **Горизонтальный overflow не проверяется.** `LayoutOverflowException` ловит только вертикальное переполнение
  (строка/страница выше доступного места; единственное место броска в `LayoutEngine.kt`). Если сумма ширин колонок
  больше ширины контентной области, колонки молча вылезут за рамку. Для таблицы потока сумму ширин проверяет валидатор
  шаблона (`columns` должны давать ширину области контента с точностью 0.01 мм), но не раскладка: при раскладке документа
  на другом формате (`PageSetup`, например A3) колонки сохраняют свою ширину.
- **Толщина линии: одна константа вне шаблонных блоков.** `FrameCell.borders` (`BorderWeight.THIN`/`THICK`) и `thickness`
  блоков шаблона (`thin` 0.25 мм, `thick` 0.71 мм, число в мм) заданы по ГОСТ 2.303. Но внешняя рамка листа
  (`frameRectangle`) и сетка шапки таблицы (`drawRichHeader`) рисуются одной константой `Styles.tableBorder` (2.0pt ≈ 0.7мм).
- **Измеритель текста медленный.** `PdfBoxTextMeasurer` заново разбирает TTF на каждый вызов `measure()`; тесты, которые
  раскладывают несколько страниц (`report-cli`, `reports/specification`), требуют `maxHeapSize = "4g"` в `build.gradle.kts`.
- **Область потока: верхний резерв не реализован.** `flowRegion` срезает только низ области (блок, висящий от верхнего
  края, схлопнул бы область). В движке такого случая нет.
- **Блоки шаблона не из слотов** (`stamp`, `leftMargin`, ... на пути спецификации) участвуют в расстановке и `reserves`, но
  основным движком не рисуются; рисует их `layOutTemplate` (путь `TemplateMain`).

## Шаблоны (YAML)

- **Поворот текста только 0 и 90.** В Layout IR нет других ориентаций. `rotate: 270` у `text`, у ячейки шапки потока и
  итоговый поворот ячейки таблицы (поворот блока + ячейки) не 0 и не 90 дают ошибку валидации с YAML-путём. Таблица с
  `rotate: 270` читается только если у каждой ячейки `rotate: 90`.
- **Один `flow` с `table:` на шаблон**, внутри набора (`blocksets`) `flow` недопустим (`only one flow table per template`,
  `flow table is allowed only at the top level`). `${param.x}` в таблице потока не поддерживается.
- **`repeat.from` не резолвится:** разбирается, но строк не даёт (`repeat: {count: N}` работает, но тестами и прогонами
  практикума не покрыт).
- **Bind только скалярный**, составных значений (`${a}/${b}`) нет; `text:` всегда литерал.
- **Один шрифт в `TemplateMain`** (GOST Type B), поле `style` вне таблицы потока в CLI игнорируется. `flow` без `table:`
  ничего не рисует.
- **Блок `flow` с таблицей рисуется от левого поля листа** на каждой странице; `size`, `attach`, `reserves`, `when` кроме
  `all` у него недопустимы.

## Таблица потока

- **Шапка: повёрнутый текст рисуется только первой строкой переноса** (и в однорядной, и в многоуровневой шапке): текст
  повёрнутой ячейки должен помещаться в её высоту целиком (`header.height` или сумма высот объединённых рядов), иначе обрезан.
  Для ячеек шапки без `lines` и без `rotate` перенос идёт по ширине колонки, а `header.height` фиксирован: при крупном кегле
  высоту надо увеличить руками.
- **Тексты шапки только литералы** (без bind, формата, `cases`), `span` / `rowSpan` только в форме `header.rows`.
- **Нет правого выравнивания** в таблице потока (`align: right` даёт ошибку загрузки `expected left|center`); числа
  выравниваются влево или по центру.
- **Нет жирного шрифта.** `bold` это только флаг стиля: гарнитура `GOST Type B` одна, начертания bold не загружено.
  Строка итога (`totalText`) и `heading` поэтому отличаются гарнитурой (Type B), а не весом.
- **Итоги: нет вложенных подитогов подгрупп и накопительных (running total) итогов.** `label` литерал (подстановки значений
  нет), `min` / `max` только числа (не Date / String), `scope: group` требует `groupBy`. `avg` требует явные `scale` и
  `rounding`. Значение итога не часть записи `item` (строки данных его не видят).
- **`groupBy` только по enum-полю**, без вложенных групп, подстановки значений в `titles`; сортировка по `sequence`
  невозможна. Каждое значение enum схемы обязано быть в `order` или `omit`.
- **Количество: отображение и расчёт расходятся по умолчанию.** `format` (`0.##`, `0`) влияет только на вид ячейки;
  `computed` (например `cost = qty * price`) и `totals` считают по точному значению поля. Показанное количество,
  округлённое форматом, умноженное на цену, может не совпасть с показанной стоимостью. Это не ошибка движка, а свойство
  шаблона: округляйте явно (`scale` + `rounding` у `computed`).
- **Нумерация строк:** одна колонка `${line.number}` на таблицу, только при фиксированном `rowHeight`, число без формата
  (нет ведущих нулей, нет шага, нет нумерации по группам; для группы есть `computed.sequence` со `scope: group`), колонка
  должна вмещать число целиком. Значение `lines.fill` по умолчанию (`false`: пустые строки без номера) выбрано как прежний
  вид листа; владелец формы ещё не решил, нумеровать ли пустые строки.
- **Сортировка строк зависит от JDK:** натуральный порядок строк использует `java.text.Collator` (локаль `ru`, сила
  `PRIMARY`); порядок русских слов определяется данными локали JDK. Смена JDK теоретически может поменять порядок
  равных на PRIMARY слов. Эталоны (golden) это не ловят, пока в данных нет таких случаев.
- **Имя исходной строки в ошибке ищется по равенству полей** (`FlowCellRenderer`: `source row N {...}`): две полностью
  одинаковые строки данных получат номер первой. Для диагностики этого достаточно, источником истины это не является.

## Данные и `--data`

- **Теги `!int`, `!bool`, `!decimal`, `!date` не покрыты положительным прогоном** (тесты и практикум используют `!str` и
  `!enum`; `!int` встречается только в тесте ошибки). Вывод типа по виду значения (`3`, `1.5`, `2026-01-31`, `true`) работает.
- **В `--data` списки скаляров не поддержаны** (карта = `Record`, последовательность карт = `List`).
- **Поле, у которого в разных строках разные типы, это ошибка** (кроме слияния `Integer` + `Decimal`): тегируйте значения
  в каждой строке.

## Тесты и проверка

- **PDF шаблонов глазами не проверялся.** Практикум и golden сверены по SVG и по числам Layout IR; PDF для
  `runTemplate` генерируется, но визуальной проверки (например через `pdftoppm`) для новых шаблонов не было.
- **Первая страница спецификации: новая видимая линия.** После правила «нижняя граница последней строки рисуется всегда»
  (`81fa21d`) слева от основной надписи (x 2000..8500, в сотых мм) появилась тонкая линия, закрывающая таблицу; на странице
  с низким штампом линия целиком ложится на толстую границу штампа. Golden это фиксируют, визуального осмотра PDF не было.
- **Determinism infra** (сквозная задача dev-plan) не реализована как отдельная инфраструктура; повторяемость сейчас
  держат golden-эталоны: SVG и PNG (рендереры) и текстовые дампы Layout IR (`reports/specification/.../golden/*.txt`). Это
  структурное сравнение Layout IR, но оно написано под отдельные сценарии, а не общий механизм.

## Шрифты

- **GOST Type A всё ещё заглушка** (PT Sans Regular): реального чертёжного шрифта Type A нет. См.
  [fonts-and-licensing.md](fonts-and-licensing.md).
- **`TextStyle.fontFamily` остаётся `String`**, не sealed-типом (константы в `FontFamilies`); резолвер
  (`DefaultFontRegistry.resolve`) отдаёт GOST Type B для `GOST_TYPE_B` и PT Sans для всего остального, поэтому опечатка в
  имени семейства тихо даёт PT Sans. Trade-off между гибкостью (report builder может назвать любой шрифт) и
  безопасностью.

## Отчёты и данные

- **`SpecificationItem` не содержит полей Формат/Зона/Примечание.** Реальная форма 1 ГОСТ 2.106 имеет эти графы, но
  доменная модель (`report-data/SpecificationData.kt`) их не несёт: в `gost-spec.yaml` колонки `format` и `zone` пустые
  (`~`), а `note` содержит единицу измерения только у материалов. Расширение модели: когда появятся реальные данные.
- **Количество в `SpecificationItem` это `Double`**, в схему данных оно попадает как `BigDecimal.valueOf(double)` (кратчайшая
  десятичная запись double). Значения Loodsman (`minQuantity` / `maxQuantity`) приходят Double, точнее их не представить.
- **Известные отличия YAML-формата количества от прежнего кода** только для отрицательных и нечисловых значений
  (недостижимы для данных Loodsman); см. комментарий `SpecificationQuantityFormatTest`.

## Закрыто (убрано из списка)

Чтобы не искать по истории: **минимальная высота строки 8 мм** (теперь `rowHeight: 8` в YAML, фиксирована);
**`report-api` без реализации** (есть `report-loodsman` и `report-server`); **резолвинг шрифта руками в каждом consumer'е**
(общий `DefaultFontRegistry` в `report-layout`, его используют `report-cli` и `report-server`); **жёстко зашитые группы и
формат количества в `Specification.kt`** (теперь `groupBy` / `cases` / `format` в YAML); **сборочные единицы терялись при
выгрузке из Loodsman**; **заголовок группы-сирота в конце страницы** (цепочка `keep.titleChain`); **параметры `${...}` в
`text:`** (литерал, подстановки нет по решению, см. [changelog-engine.md](changelog-engine.md)).
