# Ведомость покупных изделий

Отчёт запускается от головной сборочной единицы и обходит её состав сверху вниз.

## Правила отбора и группировки

- Покупным считается стандартное или прочее изделие с атрибутом «Источник поступления» = «Покупное».
- Изделия делятся по виду: болты, винты, кольца, подшипники, шайбы, шпонки и прочие покупные изделия.
- Внутри каждого вида обычные строки располагаются по алфавиту.
- Изделия, найденные внутри узла или раздела «Подборные элементы», располагаются после обычных строк своего вида, также по алфавиту.

## Собственные ведомости вложенных узлов

Собственная ВП головного объекта игнорируется: отчёт строится по его составу.

Если собственная ВП найдена у вложенного узла, его состав дальше не раскрывается. Вместо его покупных изделий в самом конце отчёта появляется группа с неизменяемым заголовком «Ведомость покупных изделий составных частей».

Строка ссылки заполняется так:

- «Наименование» — обозначение и наименование вложенного узла;
- «Обозначение документа на поставку» — обозначение собственной ВП этого узла;
- остальные колонки остаются пустыми.

Связь с собственной ВП должна быть загружена как связь `DOCUMENT`, а документ должен иметь тип «Ведомость покупных изделий».

## Количество и диапазоны Loodsman

ГОСТ Р 2.106-2019, пункт 4.5.3.6, требует указывать в ВП одно количество покупных изделий на одно изделие. Отдельной записи диапазона форма ВП не предусматривает. Пункт 4.5.3.9 требует суммировать количество на изделие, в комплекты и на регулирование.

Если Loodsman возвращает диапазон количества:

- при одинаковых границах используется это точное значение;
- при разных границах в расчёте используется только нижняя граница `minQuantity`; `maxQuantity` в произведении по пути и в итогах не участвует;
- отрицательный, перевёрнутый или нечисловой диапазон считается ошибкой исходных данных.

Для каждого пути количество равно произведению `minQuantity` всех связей «Состоит из ...» от корня до покупного изделия. Повторные вхождения затем суммируются раздельно по графам «На изделие», «В комплекты» и «На регулирование». Это правило является правилом данного модуля: ГОСТ задаёт содержимое количественных граф, но не устанавливает способ преобразования диапазона Loodsman в одно число. ГОСТ Р 2.503-2023 определяет правила оформления изменений документов и отдельного правила выбора границы диапазона не содержит.

## Основные файлы

- `reports/purchased-items/src/main/kotlin/dev/reportgenerator/reports/purchaseditems/PurchasedItemsTraversal.kt` — обход состава и правила отбора;
- `reports/purchased-items/src/main/kotlin/dev/reportgenerator/reports/purchaseditems/PurchasedItemsDataContext.kt` — подготовка строк для шаблона;
- `reports/purchased-items/src/main/resources/purchased-items.yaml` — форма и порядок групп;
- `report-loodsman/src/main/resources/loodsman-mapping.yaml` — соответствие типов и связей Loodsman внутренней модели.

## Форматы результата

Формат выбирается параметром HTTP-запроса:

- `POST /purchased-items/{versionId}` или `?format=pdf` — один многостраничный PDF;
- `?format=svg` — отдельный самостоятельный SVG на каждый лист;
- `?format=both` — PDF и SVG-листы одновременно.

Значение по умолчанию — `pdf`, чтобы существующий модуль Loodsman продолжал работать без изменений. SVG можно скачать по адресу `/reports/{id}/pages/{page}.svg`. В SVG встроены те же TTF-шрифты ГОСТ, которые используются при формировании PDF.
