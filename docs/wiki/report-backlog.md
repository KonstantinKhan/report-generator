# Актуальные задачи по отчётам и контекст для передачи

Страница для того, кто принимает доработку отчётов (человек и его агент). Сверена с кодом 2026-11-16, ветка `main`
(merge-коммит `1eeee22`), рабочая ветка `refactor/dsl`. Что уже сделано и как устроено, см. в страницах отчётов;
здесь только то, что **не закрыто**, и то, что нужно знать, чтобы не потерять время.

Отчёты: [Спецификация](specification-table-format.md), [Групповая спецификация](group-specification.md),
[Ведомость спецификаций](specification-list.md). Общие гэпы движка и шаблонов: [known-gaps.md](known-gaps.md).

## Контекст для агента

### Стек и правила проекта

- Kotlin, Ktor (сервер и HttpClient), тесты Kotest `ShouldSpec`. JDK 21, `./gradlew` из корня.
- Документация только в `docs/wiki`, README модулей не создаются. Язык чата и документации русский.
- Субагент после Execute обязан показать `git diff`: раньше субагенты тащили лишние зависимости в gradle.
- Работа с REST API Loodsman: skill `loodsman-rest-api`. MCP `loodsman` (поиск эндпоинтов и DTO) доступен только главному
  агенту и субагентам с полным набором инструментов; на момент написания он не подключался (`ECONNREFUSED`).
- Рамки/штамп/ПЗ листов спецификаций живут в YAML-шаблонах `report-ir/src/main/resources/templates/`
  (`gost-spec.yaml`, `gost-group-spec.yaml`, `gost-spec-list.yaml`), адаптер: `GostSpecTemplate` (`PORTRAIT`,
  `GROUP_LANDSCAPE`, `LIST_LANDSCAPE`). Шаблоны `report-cli/.../templates/` боевой движок не читает.

### Как запустить и посмотреть результат

- Сборка и тесты: `./gradlew build`; быстро по отчётам: `./gradlew :reports:specification:test :report-ir:test :report-server:test`.
- Golden-эталоны: `reports/specification/src/test/resources/golden/*.txt` (текстовый дамп раскладки). Файла нет, тест его
  создаёт; чтобы перегенерировать, нужно удалить файл (флага обновления нет). Перед перегенерацией скопировать старый и
  посмотреть diff: менять должно только то, что менялось намеренно. `GOLDEN_PDF_DIR=<папка>` при прогоне golden-теста
  пишет PDF; дальше `pdftoppm -r 80 -png файл.pdf префикс` и просмотр картинки.
- Реальный документ с Loodsman: сервер `./gradlew :report-server:run`. Нужны переменные окружения `LOODSMAN_BASE_URL`,
  `LOODSMAN_DB_NAME`, `LOODSMAN_USERNAME`, `LOODSMAN_PASSWORD` (образец имён: `.env.example`; значения в репозиторий
  не попадают), необязательные `REPORT_OUTPUT_DIR` (по умолчанию `/data/reports`, для локального запуска задать свою
  папку) и `SERVER_PORT` (8080). Старт занимает около минуты: сервер загружает метаданные Loodsman. Затем
  `curl -X POST "http://localhost:<порт>/specification-lists/<versionId>"` (аналогично `/specifications/`,
  `/group-specifications/`); ответ `{id, path}`, `path` это готовый PDF. Query `customerRepresentative=false` выключает блок ПЗ.
- Эталонный объект для ВС: версия `4757` (изделие «Рессорное подвешивание», `АГ52.289.047`): 4 записи, у каждой один
  родитель. Объекта с несколькими родителями на реальных данных не искали (нужен для проверки колонки «Куда входит»).

### Ловушки, на которые уже наступили

- `PageFormat.A3` в `report-geometry` портретный (297 x 420). Альбомный A3 в коде ВС: локальная константа `A3_LANDSCAPE`.
- В YAML поворот текста (`rotate: 90`) несовместим с ручным переносом `lines`: loader отклоняет. Перенос автоматический.
- Enum схемы `section` в ВС сужен до `ASSEMBLY`, `KIT`: validator требует, чтобы каждое значение было в `groupBy.order`
  или `omit`.
- `FrameSpecs` читает все слоты шаблона (`leftMargin`, `specLeft`), у шаблона ВС их нет, поэтому рамка берётся напрямую
  из `GostSpecTemplate.LIST_LANDSCAPE.frameSpec(StaticSlot.X)`.
- Нумерация строк делается движком (`${line.number}`, `lines:` в шаблоне), не кодом. Подробности и границы: раздел
  «Нумерация строк» в [specification-list.md](specification-list.md).
- Атрибут «Индекс заказчика» на тестовой базе Loodsman не найден (`optional attribute 'Индекс заказчика' not found`):
  блок ПЗ рисуется, но пустой, у всех трёх отчётов.

## Задачи: Ведомость спецификаций

Приоритет: сверху вниз. Пункты 1–3 требуют решения владельца (спросить до начала работы).

1. **Источник «Наименования».** Сейчас во всех строках колонка «Наименование» равна «Спецификация»: код берёт `Name`
   документа «Спецификация», а в Loodsman у документа такое имя (`designationAndName()` в
   `ProductNodeSpecification.kt`, вызывается из `SpecificationListData.kt`). Нужно решить: оставить так или брать
   наименование самого объекта (изделия: «Рессорное подвешивание»). Правка в одном месте.
2. **Нумерация заголовков групп и спейсеров.** Владелец хочет номер у каждой строки таблицы. Движок нумерует только строки
   записей и дозаполнение. Для заголовков групп («Сборочные единицы», «Комплекты») и пустых спейсеров вокруг них нужна
   опция в движке, например `lines.groups: true`. Что править: `report-layout/.../TableMeasurement.kt` (`numbered = false`
   у заголовка группы `:338`, подзаголовка `:318`, спейсеров `:352-354`), `report-ir/.../Ir.kt` (`IrLineNumbers`),
   `report-ir/.../FlowTables.kt` (`:221-230`), `report-template/.../Model.kt` (ключ `lines`, `:319`) и валидатор.
   Счётчик в `LayoutEngine.kt` (`:237`, `:250`, `:267`, `:293`) менять не нужно. Итоги (`totals`) в ВС не используются.
   Владелец ранее просил движок без нужды не менять: подтвердить.
3. **Лишние пустые строки вокруг заголовков групп.** Две пустые строки над «Сборочные единицы» и одна между группами:
   отступы группы из `gost-spec-list.yaml` (раздел `groupBy`/spacers). Если все строки нумеруются (п. 2), они получат
   номера, и выглядит это странно: предложено оставить один отступ.
4. **Первая страница с ПЗ.** Остаток высоты 5 мм меньше строки 8 мм, поэтому дозаполнения и номеров под зазором нет
   (`remainder: first: gap`). Решить: `first: stretch` (растянуть последнюю строку) или оставить зазор.
5. **Разрыв записи между страницами.** Строки родителей одной записи могут уйти на следующую страницу без обозначения и
   наименования: выглядит как сироты. Нужно удержание записи целиком (`keep` настроен только для заголовка группы).
   Проверить, умеет ли движок `keep` для физических строк записи.
6. **Правило ВС по пути.** Узел с ВС пропускается вместе с поддеревом, но тот же объект, достижимый из другого (не ВС)
   узла, попадает в список. Подтвердить с владельцем, как должно быть (исключать объект, если он входит хотя бы в одну
   ветку с ВС, или оставить).
7. **Последняя строка страниц 2+.** Остаток высоты уходит в последнюю строку (`remainder: stretch`), она выше 8 мм.
   Возможно, растягивать нужно только пустые строки.
8. **Проверка «Кода документа» на живом Loodsman.** Атрибут «Код документа» (`AttributeKey.DocumentCode`, маппинг
   `documentCode` в `report-loodsman/src/main/resources/loodsman-mapping.yaml`, вид «Ведомость», `optional: true`)
   не сверен с реальным именем в Loodsman. При несовпадении имени правило ВС молча не работает (сервис при этом стартует).
   Проверить через MCP `loodsman` или запросом REST API (skill `loodsman-rest-api`); найти объект, у которого есть ВС,
   и убедиться, что он пропускается. Рассмотреть: делать ли атрибут обязательным.
9. **Многородительский случай на реальных данных.** Найти объект с несколькими родителями, сформировать PDF и проверить
   колонку «Куда входит» (на 4757 такого нет).
10. **Тяжёлый запрос.** `specificationListQuery` грузит полный состав (включая детали и стандартные изделия), тяжелее
    `specificationQuery`. Оценить время на большом изделии; при необходимости ограничить запрос типами «Сборочная единица»
    и «Комплект» и их документами.
11. **«Примечание».** Колонка пока пустая (в ТЗ: «пока не заполняем»). Когда понадобится источник, описать в
    [specification-list.md](specification-list.md) и тестах.
12. **Вынести `A3_LANDSCAPE`** в `report-geometry` рядом с `A4_LANDSCAPE` и заменить локальную константу.
13. **IDE-предупреждения в новых тестах.** `SpecificationListGoldenTest.kt`: имена функций `L`, `R`, destructuring;
    `SpecificationListTest.kt`: `CanConvertToMultiDollarString`. Проверить, остались ли, исправить.
